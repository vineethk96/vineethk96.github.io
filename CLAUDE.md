## Project Overview

A modern React portfolio website with dynamic data management via Supabase. Features an interactive SystemMap visualization using D3.js, showcasing projects, work experience, and education with a responsive design and dark mode support.

**Tech Stack**: React 18, React Router, Tailwind CSS, Framer Motion, D3.js, Supabase (PostgreSQL + Edge Functions), AWS S3, GitHub Pages

## Development Commands

```bash
# Start development server (http://localhost:3000)
npm start

# Fetch latest data from Supabase and regenerate constants.js
npm run fetch-data

# Build for production
npm run build

# Deploy to GitHub Pages (builds + deploys to gh-pages branch)
npm run deploy

# Run tests
npm test

# Interactively delete a project or blog post from constants.js
node scripts/delete-content.js
```

## Critical Architecture Patterns

### Auto-Generated Data Layer

**IMPORTANT**: `src/data/constants.js` is AUTO-GENERATED by `scripts/fetch-data.js`. Do NOT edit this file manually.

**Data Management Flow**:
1. All portfolio content (projects, work experience, education, blog posts, system map links) is stored in Supabase PostgreSQL database
2. Supabase Edge Functions expose this data via REST endpoints
3. `scripts/fetch-data.js` fetches from these endpoints and generates `src/data/constants.js`
4. The `prebuild` hook automatically runs `npm run fetch-data` before building

**Two-tier content model**:
- **Dynamic data** (projects, work experience, education, blog posts, system map links): managed in Supabase, fetched at build time
- **Hardcoded data** (PERSONAL_INFO, PERSONAL_STORY, SKILLS, CERTIFICATIONS, SOCIAL_LINKS, EXTERNAL_LINKS, CONTACT_INFO): defined directly in `scripts/fetch-data.js` in the `generateConstantsFile` function — edit that file, then run `npm run fetch-data`

**When updating content**:
- For Supabase-managed data: update in Supabase, then run `npm run fetch-data`
- For hardcoded personal data: edit `scripts/fetch-data.js` directly, then run `npm run fetch-data`
- Never manually edit constants.js - changes will be overwritten

### Data Exports from constants.js

Import data using:
```javascript
import {
  PROJECTS,           // Array of project objects
  WORK_EXPERIENCE,    // Array of work experience objects
  EDUCATION,          // Array of education objects
  BLOG_POSTS,         // Array of blog posts
  SYSTEM_MAP_LINKS,   // Array of project relationship links for SystemMap
  TIMELINE_DATA,      // Merged & sorted EDUCATION + WORK_EXPERIENCE
  PERSONAL_INFO,      // Name, email, location, bio, etc.
  SOCIAL_LINKS,       // LinkedIn, GitHub URLs
  EXTERNAL_LINKS,     // Resume, Calendly links
  CONTACT_INFO,       // Formatted contact array
  SKILLS,             // Categorized skills object
  PERSONAL_STORY      // Introduction, journey, vision
} from '../data/constants';
```

### SystemMap Visualization

The SystemMap is a D3.js force-directed graph that visualizes relationships between projects:
- Nodes represent projects (from PROJECTS array filtered by `map_color` and `size` properties)
- Links represent relationships (from SYSTEM_MAP_LINKS array)
- Relationship types: `research-application`, `iot-platform`, `embedded-evolution`, `sensor-system`, `mobile-app`, `rest-api`, `systems-thinking`
- Each relationship type has a distinct color defined in SystemMapD3.js
- Nodes are draggable and interactive, clicking navigates to project detail page
- Force simulation parameters control physics: link distance, charge strength, collision radius

### Styling

- **Tailwind CSS** for utility-based styling
- **Dark mode** via `dark:` prefixes, controlled by localStorage and document class
- Dark mode **defaults to `true`** (dark) — `useState(true)` in `App.js`; only switches to light if localStorage has `'false'`
- Dark mode class toggled on `<html>` element via `document.documentElement.classList`
- Blueprint background pattern in dark mode (`.blueprint-bg` class in `src/index.css`)
- Custom Tailwind color tokens: `primary` (blues) and `accent` (greens) — defined in `tailwind.config.js`
- Custom fonts: `font-mono` → JetBrains Mono, `font-sans` → Inter
- `@tailwindcss/typography` plugin enabled — use `prose` classes for blog post body rendering

### Image Management

- Original images stored in AWS S3 bucket: `vineeth-portfolio-s3.s3.amazonaws.com`
- Images served at multiple sizes: `original/`, `large/`, `medium/`, `thumbnail/`
- Image paths stored in Supabase and exposed via constants.js
- Project images array structure: `{ url, alt, caption, original_url, medium_url, thumbnail_url }`

### Blog Post Rendering

- Blog post HTML content is sanitized with **DOMPurify** before rendering
- Code blocks inside blog posts use **react-syntax-highlighter**
- Body content styled with Tailwind's `prose` classes (from `@tailwindcss/typography`)

## Adding New Content

**Adding a Project**:
1. Add project entry to Supabase `projects` table
2. Include required fields: `id`, `title`, `description`, `tags`, `color`, `status`, `year`, `icon`
3. Optional SystemMap fields: `map_color`, `size` (for visualization)
4. Upload images to S3 and store URLs in `images` JSON array
5. Run `npm run fetch-data` to regenerate constants.js

**Adding Work Experience**:
1. Add entry to Supabase `work_experience` table
2. Required fields: `company`, `position`, `start_year`, `end_year`, `description`, `location`, `tags`, `achievements` (array)
3. Run `npm run fetch-data`

**Adding SystemMap Relationship**:
1. Add entry to Supabase `system_map_links` table
2. Required fields: `source` (project id), `target` (project id), `relationship` (type)
3. Run `npm run fetch-data`

## Common Patterns

**Icon Usage**:
- Icons imported from `lucide-react` library
- Icon names stored as strings in database, converted to component references in constants.js generation
- Example: `icon: Code` (where Code is from `import { Code } from 'lucide-react'`)

**Animation**:
- Use `framer-motion` for page transitions and component animations
- Wrap animated elements with `<motion.div>` and apply animation props
- Page-level animations use `<AnimatePresence mode="wait">` for route transitions

**Navigation**:
- Use React Router's `useNavigate()` hook for programmatic navigation
- Use `<Link>` component for declarative navigation
- Example: `navigate(\`/projects/\${projectId}\`)` for dynamic routes
